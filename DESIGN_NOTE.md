# TraceMind — One-Page Design Note

**Problem and approach:** Workplace knowledge changes every day. Tasks change owners, deadlines move, feedback corrects prior statements, and private records must stay private. TraceMind is a Python/SQLite evidence-first assistant with an optional local MiniLM+Qdrant vector index and selective OpenAI language interpretation. It runs as a stateful four-command JSON CLI, independently of its React Studio demo. **Model interpretation is never an authority or access-control mechanism.**

### 1. How do we choose what goes into a meeting brief?

For the requested person and date, we find the actual meetings they attend and the last relevant meeting for that client. We collect only source-visible developments since the previous meeting: task status/owner/due changes, document-version deltas, blockers, decisions, and outstanding commitments. We avoid routine communications, prefer high-impact changes, and apply the user's prior feedback—e.g. item caps, blocker priority and explicitly ignored subjects. When a model is enabled, it may select/rewrite a bounded set of **already grounded** candidates, never an unrestricted full-company transcript. Every included change, commitment, suggested source and question is linked to a permitted original record. If nothing material changed, return `nothing_new` instead of filler.

### 2. How do we remember, and who can see it?

Daily JSONL records, task state, deadlines, feedback, forget instructions and model-interpreted claims persist in SQLite across independent CLI executions. Derived claims reference actual source IDs and inherit their **organization, team/private/restricted visibility, requester scope, and as-of time**. A user can read their own private record, not another person's. Team facts can be shared across authorized teammates; personalized preferences and ignores do not transfer to another person's briefs. The optional OpenAI interpreter processes only **team-visible** candidate records, partitioned by organization/client; private/restricted bodies never enter its external evidence prompts. The Qdrant vector store likewise indexes team-only records and rechecks current permitted IDs on retrieval. A forget suppresses matching source/derived evidence for that user, including on future reingestion; shared vector erasure requires separate retention controls.

### 3. How do we know what is newest or authoritative?

We preserve original source timestamps and do not replace historical records with summaries. Structured task updates merge field by field; unstructured ownership/correction claims use provenance and **source authority before recency**. Later statements from the same authority can supersede earlier ones. Historical questions only use records available at the supplied `--at` timestamp; feedback becomes effective after the relevant day is observed. Relative Hinglish dates such as `kal` or `Friday` are resolved in Python using the author's local timezone. If two people/tasks remain plausible, the system clarifies instead of guessing. LLM output cannot introduce arbitrary sources, unsupported names, dates, or numbers into trusted memory without validation.

### 4. What do we deliberately avoid?

We do not hard-code public answer keys, read hidden/future records, send the whole workspace to a model, rely on a model for permissions, obey commands embedded inside emails, or silently send real emails/place calls. Model calls are optional, bounded, metered and backed by deterministic fallback. The Studio binds to localhost because its demo persona selector is **not real authentication**. A citation alone is not proof of full semantic entailment, and user-scoped forgetting is not universal physical deletion. Our honest evaluation is **85/85 public offline machine points**, **187 Python tests**, and **zero violations in a public-fixture privacy/source invariant audit**; human review, real OpenAI/Qdrant runtimes and hidden days 6–15 remain unmeasured.
